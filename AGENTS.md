# AGENTS.md

## Orientation

Full-stack monorepo: Fastify 5 API + Vue 3 SPA + BullMQ worker. All development runs inside Docker Compose — the host machine is never used to run services or install packages.

- Node pinned: `24.15.0`
- Package manager: `pnpm@10.34.5` (exact versions, engine-strict)
- TypeScript `5.9.3`, strict mode everywhere

## First-Time Setup

Generate `.env` and `.local/` credentials (never copy `.env.example` — secrets are blank and Compose will fail):

```powershell
# Windows PowerShell
docker run --rm --mount "type=bind,source=$($PWD.Path),target=/workspace" -w /workspace node:24.15.0-bookworm-slim@sha256:4e6b70dd6cbfc88c8157ba19aa3d9f9cce6ba4703576d55459e45efcbc9c5f5d node scripts/setup.mjs
```

```sh
# Linux / macOS
docker run --rm --user "$(id -u):$(id -g)" --mount "type=bind,source=$(pwd),target=/workspace" -w /workspace node:24.15.0-bookworm-slim@sha256:4e6b70dd6cbfc88c8157ba19aa3d9f9cce6ba4703576d55459e45efcbc9c5f5d node scripts/setup.mjs
```

Then:

```sh
docker compose --env-file .env -f infra/compose.dev.yaml build devtools
docker compose --env-file .env -f infra/compose.dev.yaml run --rm devtools pnpm install --frozen-lockfile
docker compose --env-file .env -f infra/compose.dev.yaml run --rm devtools pnpm build
```

## Developer Commands

All commands run from repo root. Prefix infra commands with `docker compose --env-file .env -f infra/compose.dev.yaml`.

| Goal | Command |
|---|---|
| Start infra (postgres, redis, rustfs) | `… up -d postgres redis rustfs` |
| Run DB migrations | `… run --rm migrate` |
| Init S3 bucket | `… run --rm storage-init` |
| Start apps | `… up -d web api worker` |
| View logs | `… logs --tail 100 api worker web` |
| Stop (keep data) | `… down` (**never** `down -v` unless destroying data) |
| Full CI gate | `… run --rm devtools pnpm check` |
| Smoke / integration test | `… run --rm devtools pnpm test:integration` |

### Root `pnpm` scripts (run inside devtools container or after installing locally)

```sh
pnpm check          # lint + typecheck + boundaries + api:check + format:check — must pass before PR
pnpm lint           # ESLint (apps packages scripts)
pnpm typecheck      # pnpm -r typecheck
pnpm format         # prettier --write .
pnpm format:check   # prettier --check .
pnpm check:boundaries  # node scripts/check-boundaries.mjs
pnpm api:generate   # export OpenAPI spec + regenerate packages/api-client/src/generated.ts
pnpm api:check      # verify generated files are up to date (CI gate)
pnpm build          # pnpm -r build
pnpm db:migrate     # scripts/db-migrate.mjs
pnpm storage:init   # scripts/storage-init.mjs
pnpm test:integration  # scripts/smoke.mjs (requires all services running)
```

### Per-package dev servers (inside container)

```sh
pnpm --filter @exhibition/api    dev   # tsx watch src/server.ts
pnpm --filter @exhibition/worker dev   # tsx watch src/index.ts
pnpm --filter @exhibition/web    dev   # vite --host 0.0.0.0
```

## Monorepo Layout

```
apps/
  api/      — Fastify 5 REST API + Swagger
  worker/   — BullMQ consumer
  web/      — Vite 8 + Vue 3 SPA
packages/
  contracts/   — TypeBox schemas (no @exhibition/* deps)
  db/          — pg connection pool (no @exhibition/* deps)
  backend/     — service container: DB, Redis, S3, BullMQ
  api-client/  — openapi-fetch client wrapping generated types
```

## Architectural Boundaries (enforced by ESLint + `check:boundaries`)

Violations fail `pnpm check`. Do not add imports that cross these lines:

| Package | May import |
|---|---|
| `web` | `api-client`, `contracts` only. Never `node:*`, `backend`, `db`, `ai` |
| `api-client` | `contracts` only |
| `contracts` | nothing internal |
| `db` | nothing internal |
| `backend` | `db`, `contracts`. Never `ai` |
| `api` | `backend`, `contracts` |
| `worker` | `backend`, `ai` (when it exists) |

Relative imports (`./`, `../`) cannot escape their own package root.

## TypeScript Module Resolution Quirks

- All packages: `module: NodeNext` — relative imports **must use `.js` extension** in compiled output.
- Package `exports` include `"development": "./src/index.ts"` condition — Vite and scripts consume source TS directly without a pre-built `dist/`.
- `apps/web`: `moduleResolution: Bundler`, Vite conditions `['development', 'browser']`.
- Scripts run as: `node --import tsx --conditions=development scripts/*.mjs`.

## Generated Files (committed to git)

These two files are committed and **must stay in sync** with the API code. Regenerate after any route/schema change:

```sh
pnpm api:generate
```

- `docs/api/openapi.json`
- `packages/api-client/src/generated.ts`

`pnpm api:check` fails CI if they are stale.

## Environment Variables

`.env` is generated by `scripts/setup.mjs`. Key variables agents may need:

| Variable | Value in Docker network | Host-accessible |
|---|---|---|
| `PGHOST` | `postgres` | `localhost:55432` |
| `REDIS_HOST` | `redis` | `localhost:56379` |
| `S3_ENDPOINT` | `http://rustfs:9000` | — |
| `S3_PUBLIC_ENDPOINT` | — | `http://localhost:19000` |
| `WEB_ORIGIN` | — | `http://localhost:5173` |
| `API_INTERNAL_URL` | `http://api:3000` | `http://localhost:3000` |

**S3 dual endpoints**: Internal backend code must use `S3_ENDPOINT` (Docker DNS). Signed URLs for browsers must use `S3_PUBLIC_ENDPOINT`.

## Docker Volume Isolation

Each workspace has its own named Docker volume for `node_modules` (e.g., `root_modules`, `web_modules`, `api_modules`). This prevents Windows host `node_modules` from conflicting with Linux container builds. Never install packages on the host — always use the devtools container.

## Vite Polling

`apps/web/vite.config.ts` sets `usePolling: true, interval: 500` so Windows file changes propagate into the Linux container.

## Testing

No unit test runner yet (Vitest/Playwright deferred). Current automated test is the smoke test:

```sh
docker compose --env-file .env -f infra/compose.dev.yaml run --rm devtools pnpm test:integration
```

Requires all services healthy: PostgreSQL with `pgvector`, Redis, RustFS, API (`/api/health`, `/api/ready`), Worker (BullMQ probe queue).

When unit tests are introduced: co-locate as `*.test.ts` alongside source files; cross-app tests go in root `tests/`.

## Worker Liveness

Worker writes `Date.now()` to `/tmp/exhibition-worker-health`. Compose healthcheck verifies mtime < 30 s.

## Git & Task Conventions

- Branch naming: `feat/issue-<N>-<slug>`, `fix/issue-<N>-<slug>`, `chore/issue-<N>-<slug>`
- PR titles must include `Closes #<N>`
- Commit messages: Conventional Commits in **简体中文** (`feat: 添加...`, `fix: 修复...`, `chore: ...`)
- After merging: update `tasks.md` and `docs/issues/manifest.json`
- Gate: `pnpm check` must pass (0 errors) before pushing

## After Code Changes — Restart Services

After modifying any source file, restart the affected service(s) so the running container picks up the changes:

```sh
# API changed
docker compose --env-file .env -f infra/compose.dev.yaml restart api

# Worker changed
docker compose --env-file .env -f infra/compose.dev.yaml restart worker

# Web (Vite) changed — Vite hot-reloads automatically; only restart if HMR stalls
docker compose --env-file .env -f infra/compose.dev.yaml restart web

# Multiple services changed at once
docker compose --env-file .env -f infra/compose.dev.yaml restart api worker
```

> **Rule:** every code change session must end with the relevant service(s) restarted and their logs checked (`logs --tail 50 <service>`) before marking work done.
