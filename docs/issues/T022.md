## 通用交付要求

- 每项变更遵循 `docs/REQUIREMENTS_AI_DEVELOPMENT.md` 第 6 节；接口/迁移/业务/入口/Client/Web 在本 Issue 范围内一起交付。
- 开发 Web、API、Worker、PG、Redis、RustFS 全部运行在 Docker Compose；验证通过容器执行，记录实际命令与结果。
- Docker 命令以 T002 交付的 `docs/DEVELOPMENT.md` 为准。应用功能 PR 至少运行容器内 `pnpm check`、`pnpm build` 以及本项相关集成/E2E；文档评估任务只检查链接、范围、依赖和评审结论，不机械运行无关应用测试。
- 业务有迁移时验证空库与上一版本升级；接口变更同步生成 OpenAPI/Client；涉及操作即时记录审计，真实调用即时记录费用。
- 一个 Issue 对应一个分支和 PR；分支 `feat/issue-<number>-<slug>`（工程用 `chore/`，修复用 `fix/`），PR 使用 `Closes #<number>`。
- 前置 Issue 的代码合并并通过相关验收后再从更新后的默认分支开发；不批量创建空功能分支/空 PR。
- PR 说明实际检查、迁移影响和未验证条件。PR 合并且本项验收通过后才勾选根 `tasks.md`；关闭为不计划或转移范围不算实现完成。
