# Issue 169: [P1] 项目负责人可被设置为 viewer、disabled 用户或非成员

## 问题描述

项目创建和负责人转让接受任何现有用户作为负责人，包括停用用户、viewer 角色或非项目成员。

## 位置

- `packages/backend/src/modules/projects/projects.service.ts`
- `packages/backend/src/modules/projects/projects.repository.ts`
- `apps/api/src/modules/projects.ts`
- `packages/db/src/schema/projects.ts`

## 复现步骤

1. 获取一个已启用的 viewer、已停用的用户或无关用户 ID
2. 作为管理员，使用该 `ownerId` 创建项目或调用 `POST /api/v1/projects/:id/transfer-owner`
3. 检查项目负责人和成员记录

## 当前行为

当用户存在时操作成功。在分配所有权之前，没有验证目标用户是否已启用、具有允许的角色或是项目成员。

## 期望行为

负责人必须是具有允许的项目负责人角色的已启用用户。转让应要求现有成员资格，或在所有权更改的同时原子地添加用户。

## 证据

- Service-double 验证直接将非成员目标传递给 `updateOwner`
- 项目架构仅通过外键强制负责人用户存在
- 在创建/转让路径中不会发生目标状态、角色或成员资格查找

## 根本原因

所有权验证依赖于引用完整性，但忽略了角色、状态和成员资格的域不变量。

## 提议的修复

在与项目创建或转让相同的事务中验证目标用户状态/角色和成员资格。为无效目标返回明确的 422/403 错误。

## 验收标准

- [ ] 停用/viewer 用户不能成为负责人
- [ ] 非成员不能成为负责人，除非原子地添加
- [ ] 有效的负责人转让仍然是原子的且冲突安全
- [ ] 创建和转让使用相同的验证策略
- [ ] 相关测试通过
