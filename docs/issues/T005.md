# [T005] 建立容器 CI 与 Issue/PR 交付门禁

阶段：M0  
需求依据：§13.3、§15；tasks.md  
前置任务：[T002 #2](https://github.com/bao-linfeng/exhibition-ai/issues/2)、[T003 #3](https://github.com/bao-linfeng/exhibition-ai/issues/3)、[T004 #4](https://github.com/bao-linfeng/exhibition-ai/issues/4)
目录范围：.github/workflows；.github/pull_request_template.md；scripts；tests；docs/DEVELOPMENT.md  
GitHub Issue：[#5](https://github.com/bao-linfeng/exhibition-ai/issues/5)；PR：尚未创建。

## 目标与范围

CI 在隔离 Compose 环境执行 lint/typecheck/boundaries/api:check/unit/build；提供真实依赖集成与E2E入口；PR模板要求Issue、目录、迁移、Docker验证与未验证项。

## 验收清单

- [ ] 干净runner可重建镜像并执行检查，不读取开发数据卷
- [ ] CI只使用无敏感数据与Mock，不自动调用付费模型
- [ ] PR可追踪关联Issue及依赖；失败检查阻止标记完成，模板不把未运行CI预填为通过

## 通用交付要求

- 每项变更遵循 `docs/REQUIREMENTS_AI_DEVELOPMENT.md` 第 6 节；接口/迁移/业务/入口/Client/Web 在本 Issue 范围内一起交付。
- 开发 Web、API、Worker、PG、Redis、RustFS 全部运行在 Docker Compose；验证通过容器执行，记录实际命令与结果。
- Docker 命令以 T002 交付的 `docs/DEVELOPMENT.md` 为准。应用功能 PR 至少运行容器内 `pnpm check`、`pnpm build` 以及本项相关集成/E2E；文档评估任务只检查链接、范围、依赖和评审结论，不机械运行无关应用测试。
- 业务有迁移时验证空库与上一版本升级；接口变更同步生成 OpenAPI/Client；涉及操作即时记录审计，真实调用即时记录费用。
- 一个 Issue 对应一个分支和 PR；分支 `feat/issue-<number>-<slug>`（工程用 `chore/`，修复用 `fix/`），PR 使用 `Closes #<number>`。
- 前置 Issue 的代码合并并通过相关验收后再从更新后的默认分支开发；不批量创建空功能分支/空 PR。
- PR 说明实际检查、迁移影响和未验证条件。PR 合并且本项验收通过后才勾选根 `tasks.md`；关闭为不计划或转移范围不算实现完成。

## 执行与回填

- [ ] 前置任务已合并并可用；确认当前代码和锁文件，不将目标目录当作已实现。
- [ ] 本项范围实现及相关验证完成，记录证据。
- [ ] PR 已合并到默认分支，验收全部通过。
- [ ] 回填 `tasks.md`、`docs/issues/manifest.json` 的真实 Issue/PR 链接和状态。

P1/P2 任务在其前置阶段完成后排期。标注“评估”的任务只交付需求决策，不能据此宣称相关产品功能已完成。
